Explicit anti-patterns (DO NOT DO):

These are patterns the LLM keeps re-introducing despite canon. Each iteration of the lint gate that catches them costs a redispatch — preventing them up front converges Phase 4 in fewer beats.

1. **GSAP repeat math — use `Math.floor`, not `Math.ceil`.** Scenes have a fixed `data-duration`; if the total animation length (`(repeat + 1) * cycleDuration`) exceeds it, the capture engine truncates mid-cycle and a visible jump appears at scene boundary.
   ```js
   // ❌ overshoots scene duration — visible jump at the cut
   repeat: Math.ceil(sceneDuration / cycleDuration) - 1
   // ❌ also overshoots (Math.ceil rounds up)
   repeat: Math.ceil(sceneDuration / cycleDuration)
   // ✅ total animation never exceeds scene
   repeat: Math.floor(sceneDuration / cycleDuration)
   ```
   Canon: see the inlined §"Load-Bearing GSAP Rules" block above — bullet "Hard-kill every scene boundary, not just captions" (the same principle: nothing animation-related may bleed past `data-duration`).

2. **Every scene element with a non-trivial entrance MUST have a paired exit pair before the scene's `data-duration` ends — `tl.to({opacity: 0})` followed by `tl.set({visibility: "hidden"})`.** This is NOT a captions-only rule; it applies to your scene's main text (headlines, attributions, kickers, body copy), key visuals, and any element whose entrance you authored with `tl.fromTo(... { opacity: 1, ... })` or that begins with `visibility: visible` in CSS. A bare `tl.to(opacity: 0)` leaves the element in DOM at `opacity: 0` — it still participates in layout calc, and later tweens (or sibling `immediateRender`) can resurrect it. With NO exit at all, the element stays visible past its scene's slot and bleeds into the next scene (the HOM-165 / HOM-213 symptom: "thesis main text stuck on screen 8s past its scene-end").

   The exit-pair MUST live inside THIS scene's IIFE timeline (the one registered on `window.__sceneTimelines["hook"]`), not deferred to root-level transitions — root-level transitions fade the SCENE CONTAINER (`#scene-hook`), not the per-element nodes inside it. Hide each element on its own.
   ```js
   // ❌ entrance only — element still on screen at scene end, bleeds into next scene
   tl.fromTo(headline, { opacity: 0, y: 24 }, { opacity: 1, y: 0, duration: 0.6 }, 0.2);
   // ❌ fade alone — element can resurrect, still occupies layout
   tl.to(headline, { opacity: 0, duration: 0.3 }, sceneDuration - 0.4);
   // ✅ fade + deterministic kill at fade-end (apply to EVERY non-trivial element)
   tl.fromTo(headline, { opacity: 0, y: 24 }, { opacity: 1, y: 0, duration: 0.6 }, 0.2);
   tl.to(headline,    { opacity: 0, duration: 0.3 }, sceneDuration - 0.4);
   tl.set(headline,   { visibility: "hidden" }, sceneDuration - 0.4 + 0.3);
   ```

   **Canon:** the "Hard-kill every scene boundary, not just captions" rule is in the inlined §"Load-Bearing GSAP Rules" block above (re-read that bullet — it is the generalisation of the captions rule). The captions-specific instance lives in `~/.agents/skills/hyperframes/references/captions.md` §"Caption Exit Guarantee" (`Read` on demand).

   The positive control is the canonical fixture's `payoff` scene (lines `tl.to(headline, { opacity: 0 }, fadeStart)` + `tl.set(headline, { visibility: "hidden" }, fadeStart + fadeDur)`) — every authored element in your scene's timeline should follow that shape at its own exit timestamp.

3. **Decoratives with `position: absolute` MUST have their CSS final coordinates landing on-canvas.** Canon: see §"Layout Before Animation" → "The process" steps 2-3 in the inlined canon above — "**The CSS position is the ground truth**; the tween describes the journey to get there." A tween whose bbox stays offscreen across **every** sample (not just the entrance starting point) means the rest-state coordinates themselves are off-canvas — an authoring defect, not an entrance journey. Do NOT use `left: -Npx` / `right: -Npx` / `top: -Npx` / `bottom: -Npx` past viewport edges as the FINAL position. Offscreen-START via `tl.fromTo()` is the canonical journey; offscreen-FINAL is broken.

4. **No free-form staged opacity reveals on content elements.** Canon for sequenced text reveal is the caption-group chain — `~/.agents/skills/hyperframes/references/captions.md` (caption group `#cg-N` with `set(visible) → fromTo → to → set(hidden)`); staged opacity-0 reveals on free-form selectors like `.line-a` / `.line-b` / `.line-c` are NOT in canon (verified absent from `references/typography.md` and `references/captions.md`). Read `references/captions.md` before authoring any sequenced reveal. Do NOT emit content elements with CSS `opacity: 0` that never reach non-zero opacity inside the scene's duration — bbox sampler flags them `invisible throughout`, which is signal noise per prewarm even when not blocking. Use the canonical caption-group chain (authored by `p4_captions_layer`) for sequenced reveals, or a single visible element instead.
